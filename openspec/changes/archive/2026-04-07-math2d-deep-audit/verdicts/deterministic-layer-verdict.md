## Key Findings

### Issue 1 — `pow2` has `export` keyword it should not have

- **File**: `deterministic-kernels.ts` line 194 (`export function pow2`)
- **Problem**: Sole callers are `exp()` (lines 893–894) and the function's own recursive guard (line 197). No external callers exist anywhere in the codebase. It is a private implementation step of `exp()` — exporting it is an oversight.
- **Fix**: Remove the `export` keyword. `@internal` tag at line 183 then accurately reflects intent. No other changes needed.

### Issue 2 — `logKernelSafe` has a wrong `@internal` tag and a stale TSDoc description

- **File**: `deterministic-kernels.ts` lines 831–834
- **Problem A**: The `@internal` tag contradicts the function's explicit presence in the `DeterministicKernels` namespace (line 998). Every other `*Safe` kernel (`expSafe`, `acosSafe`, `asinSafe`) is public without `@internal`. The tag is wrong.
- **Problem B**: The `@remarks` states that `safety.ts` delegates to this kernel, but `safety.ts` line 15 imports `log` directly — the described delegation chain does not exist.
- **Fix**: Remove `@internal`. Rewrite `@remarks` to accurately describe its role: the deterministic layer's single-argument safe log, analogous to `expSafe`, intended for consumers who use `DeterministicKernels` directly without the auxiliary layer. No API change.
