## Context

The `@lenguados/math2d` package currently carries 33 markdown files: 5 at package root and 28 in `docs/` (8 active + 2 subdirectory indexes + 18 in research/archive). These are the accumulated output of research phases, audits, and standards work.

Industry consensus (gl-matrix, three.js, pixi.js, planck.js, zod, Effect-TS, tRPC, TanStack Query) shows that published npm packages keep 1-2 markdown files: `README.md` and optionally `CHANGELOG.md`. No surveyed library has a `docs/` directory inside individual packages — all depth documentation lives on a dedicated docs site.

A Docusaurus site already exists at the monorepo root (`docs/`) with auto-generated TypeDoc API reference (`docs/docs/api/`), an `intro.md` (still default template), and autogenerated sidebars. The `package.json` `files` field already whitelists only code assets — `.md` files are never published to npm.

**Current state:**

- `packages/math2d/`: README, ARCHITECTURE, CONTRIBUTING, DOCUMENTATION_STANDARD, CHANGELOG + entire `docs/` tree (28 files)
- `docs/docs/`: intro.md (template boilerplate) + api/ (TypeDoc generated)
- Docusaurus sidebar: autogenerated from filesystem, uses `_category_.json` and frontmatter
- `docs/docusaurus.config.ts`: Deployed to `https://rndelpuerto.github.io/lenguados/`

## Goals / Non-Goals

**Goals:**

- Reduce `packages/math2d/` to 2 markdown files (README.md, CHANGELOG.md) matching industry convention
- Migrate 7 valuable narrative documents to the Docusaurus site (one stale doc excluded)
- Translate all Spanish-language documentation to English during migration
- Establish Docusaurus as the single source of truth for architecture, contributing, and design knowledge
- Preserve research/audit artifacts in git history while removing them from the working tree
- Update all cross-references (both READMEs, CLAUDE.md, .claude/rules/) to point to new locations
- Rewrite Docusaurus intro.md from template boilerplate to actual Getting Started content
- Follow Diataxis framework: Tutorials, How-to, Reference (auto-generated), Explanation

**Non-Goals:**

- Rewriting document content beyond translation and deduplication
- Building out full tutorials or how-to guides (future work)
- Changing the TypeDoc auto-generation pipeline
- Modifying runtime code, tests, or build configuration
- Creating package-level CLAUDE.md or .claude/ files
- Deploying the Docusaurus site (deployment is independent of content migration)

## Decisions

### D1: Package root keeps README.md + CHANGELOG.md + ARCHITECTURE.md (two-level pattern)

**Rationale:** ARCHITECTURE.md is a recognized root-level convention file (matklad, 2021). Research found that rust-analyzer keeps it at `docs/dev/architecture.md`, ts-graphviz (TS monorepo) keeps it at root, and deno/std keeps it at `.github/ARCHITECTURE.md`. The convention is that it lives "next to README and CONTRIBUTING" — at or near the root.

For lenguados, the two-level pattern:

- **Root `/ARCHITECTURE.md`** (NEW, 30-60 lines): Monorepo topology — which packages exist, how they relate, shared infrastructure. Points to `packages/math2d/ARCHITECTURE.md`.
- **Package `packages/math2d/ARCHITECTURE.md`** (EXISTING, ~100-200 lines): Detailed code map — 6-layer architecture, Mermaid diagram, key patterns, zero-check conventions. Analogous to rust-analyzer's `docs/dev/architecture.md`.

CONTRIBUTING.md and DOCUMENTATION_STANDARD.md are NOT convention files and do NOT stay at package root.

### D2: Docusaurus site organized by Diataxis quadrants with _category_.json

**Structure:**

```
docs/docs/
  intro.md                          (sidebar_position: 1 — Tutorial/Getting Started)
  math2d/                           (position: 2 — Explanation + Reference)
    _category_.json                 (label: "math2d", position: 2)
    architecture.md                 (position: 1 — merged arch docs)
    interoperability.md             (position: 2 — type patterns)
    edge-cases.md                   (position: 3 — IEEE 754 catalog)
    design-decisions.md             (position: 4 — ADR-style decisions)
    audit-closure-2026.md           (position: 5 — historical audit)
  contributing/                     (position: 3 — How-to)
    _category_.json                 (label: "Contributing", position: 3)
    tsdoc-standard.md               (position: 1 — TSDoc conventions)
    testing-strategy.md             (position: 2 — testing approach)
    design-philosophy.md            (position: 3 — POA/SOLID patterns)
  api/                              (position: 4 — Reference, auto-generated, unchanged)
```

**Diataxis mapping:**

- **Tutorials**: `intro.md` (getting started with lenguados)
- **How-to**: `contributing/` (TSDoc, testing, design philosophy)
- **Reference**: `api/` (auto-generated TypeDoc), `math2d/edge-cases.md`
- **Explanation**: `math2d/architecture.md`, `math2d/interoperability.md`, `math2d/design-decisions.md`

### D3: ARCHITECTURE.md stays at package root; core_principles.md content goes to Docusaurus

**Rationale:** ARCHITECTURE.md is a convention file that stays at the package root (matklad convention). It serves as the concise code map. The `core_principles.md` content (axioms, DCE policy, kill-switch strategy) is expanded architectural explanation that belongs on the docs site.

**Strategy:**

- `packages/math2d/ARCHITECTURE.md` stays and is updated: add link to Docusaurus architecture page, integrate unique content from `core_principles.md` axiom table (brief summary), merge `module_interoperability.md` type escalation gradient if space allows.
- `docs/docs/math2d/architecture.md` is created as the expanded deep-dive: design principles, axioms (translated to English), DCE policy details.
- `core_principles.md` is deleted after migration.

### D4: Research archive and stale audit doc deleted from working tree

**Rationale:** The 18 files in `docs/research/archive/` (3000+ lines) are phase artifacts from a completed research process (2025-2026). Additionally, `docs/audits/code_review_findings_2026.md` is stale — it describes SeededRandomSource as "Park-Miller LCG" when the CHANGELOG documents it was replaced with xoshiro128++. The first audit agent confirmed 100% content overlap with other documents plus this factual error.

**Deletion scope:**

- Entire `docs/research/archive/` directory (18 files)
- `docs/audits/code_review_findings_2026.md` (stale, not migrated)
- `docs/README.md` (Docusaurus sidebar replaces the index function)

### D5: All migrated documents translated to English

**Rationale:** Four documents are primarily in Spanish: `core_principles.md`, `testing_strategy.md`, `ultimate_audit_report.md`, `decisions_and_benchmarks.md`. The project's README, CONTRIBUTING, CLAUDE.md, and all code comments are in English. Spanish-only documents fragment the audience. npm packages targeting the global developer community SHALL use English for all technical documentation.

**Translation approach:** During migration, translate body text to English. Spanish "vision" or "mission" statements may be preserved as blockquotes with English translation following.

### D6: Root CONTRIBUTING.md absorbs package-specific content

**Rationale:** The root `CONTRIBUTING.md` already covers workflow, commits, hooks, testing. The package `CONTRIBUTING.md` adds design philosophy, API conventions, error handling triality. Only ~20 lines of truly unique content exist in the package file (suffix naming convention, `Readonly*Like` POJO interop example, fluent chaining rule). Merging avoids contributor confusion about which guide to follow.

**Merge strategy:** Add a "math2d API Conventions" section to root CONTRIBUTING.md covering: static+instance pattern, out parameter, triality (with suffix naming note), CS variants, apply vs transform, \*Like interfaces. Add "Detailed Guides" section with links to Docusaurus contributing pages. Remove link to package-level CONTRIBUTING.md.

### D7: Docusaurus pages get standard frontmatter and _category_.json

Each migrated document gets Docusaurus frontmatter:

```yaml
---
sidebar_position: N
title: 'Page Title'
description: 'One-line description for SEO and generated-index pages'
---
```

Each category directory gets `_category_.json` with `label`, `position`, `description`, and `link.type: "generated-index"`. This integrates with the existing autogenerated sidebar config.

### D8: Package README uses absolute GitHub URLs; root README uses relative paths

**Critical finding:** npm's markdown renderer does NOT resolve relative paths back to GitHub (npm/feedback#666, npm/cli#6206). Since npm always includes README.md in the published tarball regardless of the `files` field, relative links like `../../docs/docs/math2d/architecture.md` render as broken URLs on npmjs.org.

**Linking convention:**

- Package README → docs/repo files: Absolute GitHub URLs (e.g., `https://github.com/rndelpuerto/lenguados/blob/main/docs/docs/math2d/architecture.md`). Works on both GitHub and npm.
- Package README → deployed docs site: `https://rndelpuerto.github.io/lenguados/docs/`
- Package README → local files (CHANGELOG.md): Relative path OK (same directory resolves on both platforms)
- Root README → package/repo files: Relative paths (root README is not published to npm)
- Within Docusaurus: Relative paths without `.md` extension

### D9: Docusaurus intro.md rewritten

The current `docs/docs/intro.md` is default Docusaurus template text (mostly commented out). It SHALL be rewritten as a proper Getting Started page with project description, installation, minimal code example, and navigation links.

### D10: Content deduplication between design-decisions and design-philosophy

Industry comparison tables appear in both `decisions_and_benchmarks.md` and `clean_code_and_solid_application.md`. During migration:

- Benchmarks/industry comparisons → `design-decisions.md`
- SOLID deviations/POA principles → `design-philosophy.md`
- No content appears in both

### D11: Documentation conventions documented in three places

After restructuring, the conventions themselves must be documented so future contributors and AI agents maintain the structure:

1. **`.claude/rules/documentation-conventions.md`** (NEW) — Path-scoped rule (`**/*.md`) loaded automatically by AI agents when editing any markdown file. Contains the complete convention set: file placement, naming, linking, language, frontmatter, ARCHITECTURE.md two-level pattern.

2. **Root `CONTRIBUTING.md`** — New "Documentation" section (~15-20 lines) for human contributors. Brief bullets with links to docs site for depth.

3. **Root `CLAUDE.md`** — New "Documentation Structure" section (~5-10 lines) pointing to the rule file and giving the high-level structure overview.

**Rationale:** Without documenting the conventions, the next person to add documentation will recreate the problems we're solving (docs/ directory inside packages, Spanish documents, relative links in package READMEs, etc.). Three complementary touchpoints ensure both humans and AI agents discover the rules.

### D12: Docusaurus boilerplate cleanup

The Docusaurus site contains unmodified `create-docusaurus` scaffolding: 3 blog posts with Lorem ipsum and Docusaurus team authors, 7 backup tutorial files, and a template markdown page. These SHALL be deleted. Additionally, `docs/README.md` uses `yarn` commands while the entire project uses `npm` — this SHALL be fixed.

### D12: Emoji removal from migrated headers

Source documents use emojis inconsistently in headers (module_interoperability.md, exhaustive_edge_cases.md, clean_code_and_solid_application.md have emoji headers; ARCHITECTURE.md, README.md do not). All migrated documents SHALL have emojis removed from section headers for consistency and accessibility.

### D13: Fix stale references during migration

During migration, known stale content SHALL be fixed rather than migrated as-is:

- DOCUMENTATION_STANDARD.md: Remove 5 deleted constants from the Sub-Categories table (ITERATIVE_TOLERANCE, E, GOLDEN_RATIO, GOLDEN_RATIO_CONJUGATE, MAX_SAFE_INTEGER_F64)
- CLAUDE.md: Fix `safeDivide` → `divideSafe` typo (line 67)
- testing_strategy.md: Fix duplicate section 3 numbering
