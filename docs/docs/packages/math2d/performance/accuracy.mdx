# Numerical Accuracy

math2d uses [fdlibm](https://www.netlib.org/fdlibm/)-based deterministic kernels for all
transcendental functions (`sin`, `cos`, `tan`, `atan2`, `exp`, `log`, etc.). This guarantees
bit-identical results across platforms at the cost of some throughput compared to
native `Math.*` (which itself uses C++ fdlibm in V8).

This page documents the accuracy characteristics of those implementations.

<AccuracyOverview />

## Why fdlibm?

Native JavaScript `Math.sin` produces different results on different CPUs — Intel, ARM,
and Apple Silicon use different microcode implementations. For applications that require
determinism (networked simulations, replay systems, unit test reproducibility), this is
unacceptable.

fdlibm is the IEEE 754 reference implementation. It produces identical results on every
platform that supports `float64`, with a target accuracy of 1 ULP (one bit of rounding
error in the worst case).

<InsightCallout title="Determinism vs Performance">
 The throughput cost of JavaScript fdlibm is a deliberate architectural tradeoff.
 In a 60 fps game loop with 10K entities, transcendental functions represent
 less than 5% of total frame time — the determinism guarantee is worth far more
 than the marginal throughput difference.
</InsightCallout>
