# Auxiliary Performance

Performance analysis for the auxiliary layer — scalar arithmetic, angle operations,
numeric utilities, and deterministic kernel functions.

## fdlibm vs Native Math

The deterministic layer uses [fdlibm](https://www.netlib.org/fdlibm/) implementations
of transcendental functions (`sin`, `cos`, `tan`, `atan2`, etc.) to guarantee
bit-identical results across platforms.

<InsightCallout>
 **fdlibm trades throughput for determinism** — native `Math.sin` delegates to the platform's C++
 libm (which may use SIMD) producing subtly different results on different CPUs. fdlibm produces
 identical results everywhere, which is essential for networked simulations, replay systems, and
 unit test reproducibility.
</InsightCallout>

## Triality on Scalar Operations

Some scalar operations have the same default/safe/unchecked tier pattern. For example, floored division:

- `floorDivide(a, b)` — throws `RangeError` when `b === 0`
- `floorDivideSafe(a, b)` — returns `0` for `b === 0`
- `floorDivideUnchecked(a, b)` — no check, may produce `Infinity` or `NaN`

For measurement methodology, see [Methodology](../../../performance/methodology).
